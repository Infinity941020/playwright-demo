# Checkout Step One画面 テストケース（初版・13件）

共通の前提：standard_user でログイン済み。カートに「Sauce Labs Backpack」が1件入った状態で、
Checkout Step One画面（/checkout-step-one.html）を開いている
（TC-CO1-013 のみ未ログイン状態が前提）

前提状態の作り方：
- カートの中身は、Cart画面と同じく、ブラウザの保存領域（localStorage の cart-contents）への直接書き込みで作る（decisions.md 論点15）
- Checkout Step One画面は、URLで直接開く（Cart画面の Checkout ボタンからの遷移は TC-CART-007 で確認済みのため）

入力に使う値（特に記載がない場合）：
- 名：Taro ／ 姓：Yamada ／ 郵便番号：1000001

対応する仕様書：checkout_step_one_spec.md

テストIDの付け方：Checkout は3画面あるため、Step One を「TC-CO1」、Step Two を「TC-CO2」、Complete を「TC-CO3」とする

## ■ 対象外としたもの

| 項目 | 理由 |
|---|---|
| 未入力の組み合わせ8通りのうち、TC-CO1-002〜005 以外の3通り（名＋姓、名＋郵便番号、姓＋郵便番号が未入力） | 優先順は「すべて未入力」と「1項目だけ未入力」の確認で十分に裏付けられ、残りの組み合わせで結果が変わる可能性は低いため（Login画面の「無効×無効」除外と同じ考え方）。実機では8通りすべて確認済み |
| Step Two からブラウザの「戻る」、Cancel 後の再入場で入力値が消えること | 「本画面を離れると保持されない」ことは再読み込み（TC-CO1-011）で確認する。ブラウザの「戻る」の挙動はブラウザのキャッシュの仕組みに左右されやすく、テストが不安定になるおそれがあるため |
| 空白のみの入力、Enter キーで Cancel が動くこと、エラー時に入力済みの欄も赤くなること、カートが空でも進めること | 意図された仕様か不具合かを判断できないため（仕様書の「判断できない挙動」参照） |
| 入力値の文字種・文字数の確認 | チェック自体が存在しない（仕様書「必須項目」参照） |
| 特殊ユーザー（problem_user等） | 今後の拡張候補 |
| ハンバーガーメニュー | Logout機能で扱う |
| Step Two・Cart画面の中身 | それぞれの画面の仕様で扱う |
| 見た目の比較（Visual Regression） | Stage 2-1で扱う |
| 名だけ入力した途中の状態で Cancel を押すケース（TS版 checkout-cancel.spec.ts ③） | 入力の有無で Cancel の動作は変わらないため、未入力（TC-CO1-009）と全項目入力（TC-CO1-012）の2通りで確認する |
